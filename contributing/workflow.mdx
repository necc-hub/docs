## 文档站分支模型

文档仓只有 `main` 一个长期分支。不要创建 `develop` 或发布分支，也不要将主代码仓的分支模型套用到本仓。

| 分支 | 用途 |
|---|---|
| `main` | 发布分支；合并后由 Mintlify 自动部署 |
| `docs/<短描述>` 或 `fix/<短描述>` | 单次文档更新或修复；完成后合并并删除 |

修改前，先按[贡献指南](/contributing/guidelines)确认目标仓库：本站只接收整理后的 `.mdx`、导航和站点工具，不接收原始赛事大二进制。

## 一次完整的文档更新

### 1. 从最新 main 创建分支

```bash
git switch main
git pull --ff-only origin main
git switch -c docs/update-onboarding
```

### 2. 安装依赖并预览

```bash
npm ci
npm run dev
```

本地预览默认在 `http://localhost:3000`。详细环境和写作规范见[本地开发](/development)。

### 3. 修改内容

- 修改已有页面时，直接编辑对应 `.mdx`。
- 新增页面时，补充非空 `title`、`description`，并在 `docs.json` 对应分组注册。
- 修改导航结构时，同步更新 `AGENTS.md` 的导航说明。
- 图片放入 `images/`，以 `/images/` 开头引用；大二进制按仓库约定上传 CDN 后链接，不放入 Git。

### 4. 提交前检查

```bash
npm run check
```

该命令会运行回归测试、生成并同步 PageInsights、检查 CSS 与 Mintlify 配置，并检查导航、frontmatter 和内部链接。命令产生的 PageInsights 数据及页面挂载变更应与正文一起提交。

外链超时、登录墙、403/429 会作为警告显示；确认真实 404 或内容迁移后应修复链接。不要仅因命令退出码为 0 就忽略这些警告。

### 5. 提交并创建 PR

```bash
git add -A
git diff --cached --check
git commit -m "docs(onboarding): 更新新人学习路径"
git push -u origin docs/update-onboarding
```

提交前确认暂存区只包含本次正文、导航和生成物，没有密钥、本地配置或无关文件。

向 `necc-hub/docs` 的 `main` 创建 Pull Request，等待检查通过和审查后合并。未获维护者授权时，不要直接推送 `main`。

## 提交信息规范

使用 [Conventional Commits](https://www.conventionalcommits.org/)：`<type>(<scope>): <subject>`。

| 类型 | 适用场景 | 示例 |
|---|---|---|
| `docs` | 内容、导航、写作规范 | `docs(curc27): 更新新人学习路径` |
| `fix` | 页面渲染或工具行为修复 | `fix(insights): 修复生成物排序` |
| `ci` | CI 和检查流程 | `ci: 统一文档校验入口` |
| `test` | 测试补充 | `test: 覆盖贡献流程回归` |

## 审查与发布

审查重点：仓库归属是否正确、导航可发现性、命令能否执行、链接和图片是否有效、页面是否适用于当前赛季。

合并到 `main` 后，Mintlify 自动部署到 https://docs.newenergycoder.club/。文档站不使用 Git Flow、版本发布分支或 SemVer 发布流程；内容有更正时直接提交新 PR。
